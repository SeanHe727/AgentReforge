# Post-run coder evaluation

This directory is intentionally separate from the AgentReforge improvement
pipeline.

For fast early-version checks, use the deterministic brownfield suite in
`eval/mini/`. The larger six-problem suite in this directory remains the
high-variance capability evaluation.

The improvement pipeline ends when it has validated and committed a change to
the target coder system. It does not use the quality of code generated by that
coder as a delivery gate.

After a candidate commit exists, evaluation runs as a separate experiment:

1. Run the baseline coder and candidate coder on the same prompt, model, and
   step budget.
2. Write each coder's generated project to its own output directory.
3. Keep `TASK.md` beside each generated project.
4. Hand the two artifact directories to an external reviewer (for example
   Codex) for a lightweight score and explanation.
5. Use a formal benchmark later when a stronger capability claim is needed.

Generate artifacts without grading:

```bash
python -m eval.solve --agent /path/to/baseline --out eval/solutions/baseline
python -m eval.solve --agent /path/to/candidate --out eval/solutions/candidate
```

`solve.py` only runs the coder and persists its output. `harness.py` contains an
optional automatic LLM grader for quick iteration, while `CODEX_PROMPTS.md`
contains prompts for an explicit external review.

Evaluation reports may later be supplied to a new AgentReforge run as evidence,
but they do not retroactively change whether the candidate commit was delivered.
